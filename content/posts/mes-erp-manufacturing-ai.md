## 一张图放下所有系统

制造业的 IT 系统多到让人眼晕：ERP、MES、WMS、PLM、APS、QMS、SCADA……第一次接触很容易迷路。其实所有系统都能放进一个金字塔（ISA-95 五层模型），从上到下离"钱"越来越远、离"机器"越来越近：

```
L4  经营层    ERP   —— 管钱、订单、物料计划（月/周粒度）
L3  制造运营层 MES   —— 管车间执行：工单、工序、批次（天/小时粒度）
L2  监控层    SCADA —— 采集设备数据、监视产线（秒粒度）
L1  控制层    PLC/DCS —— 直接控制设备动作（毫秒粒度）
L0  物理层    设备、传感器、机械臂
```

一句话记忆：**ERP 决定"造什么、造多少"，MES 负责"在车间怎么造出来"，SCADA/PLC 让机器真的动起来。** 层与层之间的数据打通（系统集成）是制造业 IT 的核心痛点，也是全栈工程师的主要用武之地。

## ERP：让钱账和物账对得上

ERP 的业务本质是把企业的人、财、物、产、供、销统一管起来。代表产品：SAP（全球老大）、Oracle EBS、用友、金蝶（国产双雄）。

核心模块用 SAP 的叫法（行业通用黑话）：SD 销售、MM 物料、PP 生产计划、FI/CO 财务。两条核心业务流：**Order to Cash**（接单→生产→开票→收款）和 **Procure to Pay**（请购→采购→收货→付款）。

**ERP 的灵魂是 MRP（物料需求计划）**，一个倒推算法：

```
客户订单（8 月交 1000 台设备）
  → 查 BOM（物料清单：1 台设备 = 2 块主板 + 4 个电机 + ...）
  → 减掉现有库存和在途采购
  → 按各物料的采购/生产提前期倒排时间
  → 输出：什么时候下采购单买什么、什么时候下生产单造什么
```

BOM 是制造业最重要的数据结构——一棵多层的树（成品→部件→零件→原材料），几乎所有制造业务都围着它转。

技术形态上，传统 ERP 是单体巨兽（SAP 用自家 ABAP 语言），现在的方向是云 ERP / SaaS 化（SAP S/4HANA Cloud、金蝶云苍穹、用友 BIP），技术栈转向 Java 微服务 + 前端中台——这正是互联网背景的全栈工程师能切入的位置。

## MES：把生产订单变成车间动作

ERP 下达一张"生产订单"（造 1000 台），MES 把它变成车间里可执行的动作，并把实际发生的一切记录回来。ERP 管到"订单"粒度，MES 管到"工序、设备、操作工、物料批次"粒度。

核心功能模块：

| 模块 | 干什么 | 关键词 |
|------|--------|--------|
| 工单管理 | 接 ERP 生产订单，拆成车间工单 | 工单是状态机：下达→开工→完工→关闭 |
| 排产调度 | 哪台设备、哪个班组、什么顺序做 | 复杂排产独立成 APS 系统 |
| 工艺路线 | 产品依次经过哪些工序 | Routing、工序、工位 |
| 派工报工 | 分活 + 记录"谁在哪台设备做了多少" | 报工数据是成本核算的源头 |
| 物料追溯 | 这批成品用了哪批料 | 正向/反向追溯，质量事故的救命稻草 |
| 质量管理 | 过程检验、不良品处理 | SPC 统计过程控制 |
| 设备管理 | 设备状态、维保 | OEE |

做过电商订单系统的人看到"工单状态机"应该会心一笑：下达→开工→完工→关闭，和订单状态机是一模一样的建模。报工防重也是幂等问题的换皮。业务母题跨行业通用，这里是最好的例证。

## 制造业的"GMV 公式"：OEE

> **OEE（设备综合效率）= 时间稼动率 × 性能稼动率 × 良品率**

三个因子分别回答：设备该开的时间里真开了多少？开着的时候跑到额定速度没有？跑出来的东西有多少是好的？

世界级工厂 OEE ≈ 85%，大多数工厂只有 40%~60%——所以"提升 OEE"是几乎所有 MES 项目的立项理由。其他高频指标：良率（Yield）、WIP（在制品）、Cycle Time、准时交付率（OTD）。

## AI 在制造业的六个落地场景（按价值排序）

1. **良率分析**：从海量量测/设备数据中定位"良率杀手"，传统靠资深工程师人肉分析几天，AI 把它缩到小时级。半导体行业最值钱的场景。
2. **AOI 视觉缺陷检测**：机器视觉查外观缺陷，已大规模落地。当前升级方向是大模型做小样本缺陷分类。
3. **设备预测性维护（PdM）**：传感器时序数据预测设备故障，避免非计划停机。
4. **智能排产**：用运筹优化/强化学习解"几百个工单抢几十台设备"的排列组合问题。
5. **工艺知识助手 Agent**：把老师傅经验、SOP、设备手册、历史异常处理记录做成知识库，工程师用自然语言问"XX 设备报这个警怎么处理"。架构上就是 RAG + 工具调用 + 工单流转，**和电商客服 Agent、企业智能客服完全同构**，只是知识库换成了工艺文档。
6. **数字孪生**：虚拟工厂仿真验证排产/工艺变更。

## 制造业 AI 落地的真实难点

聊落地不能只聊场景，难点更有信息量：

- **数据孤岛严重**：各系统各管一段，ERP、MES、SCADA 的数据打不通，AI 没数据可用。
- **老设备没有数据接口**：数字化的前提是数据采集，很多工厂第一步卡在这里。
- **容错率要求比互联网高得多**：电商客服 Agent 答错一句转人工就行，工艺参数推荐错了可能报废一整批物料。所以制造业 AI 更强调"人机协同 + 置信度分级 + 审批兜底"，纯自动决策推进很谨慎。

第三点对 Agent 工程的启发很直接：**HITL（人工审批）在制造业不是可选项，是硬约束。** 我在自己的 Agent 项目里把敏感操作做成状态机层面的硬中断（审批通过前动作真实不会执行），这套设计放到制造业场景刚好是刚需。

## 求职视角的一点观察

工业软件国产化是政策强推的赛道，国产 MES/ERP 厂商（赛美特、上扬、金蝶、用友）处在扩张期，缺"懂业务的全栈"——既能写 Java 微服务 + 前端看板，又能听懂工厂黑话的人极稀缺。大湾区制造业密集，深圳/东莞/惠州的电子制造和半导体企业数字化部门常年招人。

我的定位话术是三层：系统集成（ERP/MES/WMS 打通）、现场数据可视化（车间看板、指挥中心大屏）、AI 应用（工艺知识助手、良率分析）。智能客服 Agent 的架构迁到工艺知识助手场景，改动的只是知识库内容和工具对接。
