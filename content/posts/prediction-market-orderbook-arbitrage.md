# 预测市场订单簿套利分析：从盘口价差到可成交收益

SportOracle 已有体育赛事数据、预测信息和预测市场接入资料。这次我整理的是订单簿套利的分析设计：回答某个价差是否存在、目标数量能否成交、扣除成本后剩多少，以及哪些环节会让机会失效。本文的盘口和费用均为教学假设，不是历史实盘收益；也不表示项目已经完成自动交易。

## 先区分三种价格关系

同一资产的最高买价称为 bid，最低卖价称为 ask。常见盘口中 ask 高于 bid，二者的差就是 spread。买入立即成交通常消耗 ask，卖出立即成交通常消耗 bid。中间价和最新成交价都不能替代当前可成交报价。[订单簿官方说明](https://docs.polymarket.com/market-data/prices-order-books)

| 场景 | 看到的现象 | 应该怎样理解 |
| --- | --- | --- |
| 单个订单簿 | bid 为 0.46，ask 为 0.50 | 立即买入再卖出先损失 0.04，挂单双边赚价差存在库存和成交风险 |
| 同一条件的互补结果 | YES 和 NO 的可成交买入成本之和低于对应合并价值 | 可以进一步检查是否构成完整结果集合与可执行套利 |
| 模型胜率高于市场报价 | 模型估计 60%，市场 ask 为 0.50 | 属于带模型误差的方向性判断，不能直接视为套利 |

跨市场比较还必须核对结果定义、比赛时间、是否含加时、取消规则和结算条件。两个标题接近的市场，可能对应不同的支付结果。

## YES 与 NO 的价差怎样计算

先限定一个普通二元市场：YES 与 NO 属于同一条件、互斥且覆盖完整结果，数量相等，并且可按对应协议合并成抵押资产。不能把不同条件或不同资产版本的代币凑成一组。[官方仓位管理文档](https://docs.polymarket.com/trading/positions/manage)

假设购买 100 份 YES 的均价为 0.47，100 份 NO 的均价为 0.50，每组完整结果可合并取得 1 单位对应抵押资产：

```text
购入成本 = 100 × 0.47 + 100 × 0.50 = 97
合并取得 = 100
理论毛差 = 100 - 97 = 3
示例费用及执行成本 = 1.2
分析净差 = 3 - 1.2 = 1.8
```

这里的 1.2 只是算例假设。实际计算需要读取适用市场的费用规则，并计入两腿交易、合并、网络或中介成本。不能沿用“所有市场都免费”的旧结论。[官方费用说明](https://docs.polymarket.com/trading/fees)

相反方向也可以建立分析模型：若完整结果的卖出收入高于拆分成本与费用，可以检查拆分后出售的条件。但这额外涉及抵押资金、授权和拆分状态，不能只把买入公式反过来就认定可执行。

## 最优一档只够买几份怎么办

YES 卖盘有两档：0.47 只有 20 份，0.51 有 80 份。买 100 份的成本是 50.2，均价为 0.502。若 NO 均价仍是 0.50，两腿成本已经达到 100.2，尚未扣费就没有正毛差。

因此分析器需要对目标数量逐档吃单：

```text
cost_to_buy(levels, quantity):
    remaining = quantity
    cost = 0
    for level in asks_sorted_by_price_ascending:
        take = min(remaining, level.available_quantity)
        cost += take * level.price
        remaining -= take
        if remaining == 0: return cost
    return insufficient_depth
```

这段是分析伪代码。实际实现应使用定点数或 Decimal，明确价格、数量与费用的精度和取整方式。遍历深度已经计算了价格冲击，就不要再把同一段冲击重复扣作滑点；额外预算用于覆盖快照之后价格变化等执行不确定性。

数量也不能只看两边最优档的最小值。可以沿两本订单簿的价格档位累计，找到成本约束下可支持的数量，再结合最小下单量和资金限额计算候选规模。

## 分析页面应该展示什么

我会按以下链路组织 SportOracle 的分析能力：

```text
市场与结果标识核对
    → 订单簿快照和增量更新
    → 两腿深度成本计算
    → 费用与执行预算
    → 候选机会和失效原因
    → 页面展示与记录回放
```

后端输出包含条件标识、两腿资产 ID、目标数量、均价、理论毛差、费用估算、净差、数据时间和风险原因。前端同时展示原始盘口与计算结果，让使用者能逐项复核。

数据刷新要区分加载中、数据过期、深度不足和没有候选机会。断开行情连接后保留最后一次数据可以方便观察，但必须标记过期，并暂停把旧数据当成新机会输出。不同来源的时间戳只在时钟可比较时用于偏差判断，同时记录本地接收时间。

AI 可以解释赛事背景、整理规则差异；价格乘法、深度遍历、费用计算和门槛判断交给确定性程序。机会记录保存规则与参数版本，方便回放同一份输入。

## 两腿成交仍可能失衡

第一腿买到后，第二腿可能被撤单、涨价或拒绝。此时系统持有方向性敞口，理论上的完整结果组合尚未形成。单笔 FOK 即使限制该订单必须全部成交，也不能保证另一笔订单同时成交。

设计执行链路时，需要记录每腿提交、成交、部分成交、取消和未知状态。超时后先查询订单与成交记录，再决定后续动作；盲目重发会产生重复持仓。只有双腿数量匹配且后续合并或结算路径成立，才具备相应的支付关系。

## 三类容易误判的故障

- **症状**：页面显示净差为正，尝试成交后变负。**根因**：计算使用中间价或只读取最优档。**处理**：按目标数量遍历两腿深度，列出每项费用与假设。
- **症状**：机会频繁出现又消失。**根因**：两本盘口更新不同步，或行情重连时混用旧快照与新增量。**处理**：保存订阅与快照状态，无法确认连续性时重新同步，并暂停候选输出。
- **症状**：两边都买到了，却无法合并。**根因**：条件、结果集合、资产版本或账户路径不匹配。**处理**：在计算前做身份与能力校验，错误结果不能靠相同标题强行配对。

下一步最小练习是保存两本合成订单簿，手算三档深度，再校验程序结果。至少覆盖深度不足、扣费后转负、单腿失败和行情过期四种情况；在这些行为可复核之前，不把页面上的正数称为确定收益。
