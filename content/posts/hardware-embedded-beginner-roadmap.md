# 硬件工程师与嵌入式入门：从看懂电路到完成设备闭环

一台采集设备要完成的事情很具体：正确供电，读到可信的传感器数据，处理按键与异常，再把结果交给上位机或服务端。硬件与固件分工不同，却需要围绕同一条信号链共同排查。

对已有 Web 和服务开发经验的人，我倾向于先跑通一个低压传感器采集终端。它能把电路、固件、通信和页面展示串起来，也能明确自己接下来该深入哪个方向。

## 硬件和嵌入式分别做什么

| 方向 | 主要工作 | 可检查的交付物 |
| --- | --- | --- |
| 硬件研发 | 供电、器件选型、接口、原理图与 PCB、样板调试 | 原理图、BOM、PCB、测量与验证记录 |
| 嵌入式固件 | 启动、驱动、状态机、通信、实时任务与故障恢复 | 固件、接口协议、调试记录与测试结果 |
| 上位机与服务 | 设备连接、数据展示、配置与设备管理 | 协议解析、接口、管理页面和运行日志 |

能用开发板点亮 LED，是熟悉工具链的起点。独立承担硬件设计还需要掌握电源、布局布线、器件约束、EMC 与测试；固件工作则需要继续理解资源限制、时序与异常处理。

## 电路基础先围绕测量来学

第一批概念包括电压、电流、电阻、功率、公共参考地、上拉下拉和电平阈值。

欧姆定律 `I = V / R` 可以用来估算 LED 限流电阻。实际电阻应结合供电电压、LED 正向压降和目标电流选择，同时检查器件额定功率与 GPIO 驱动能力。GPIO 的输出能力有限，电机或较大负载需要合适的驱动器件，不能直接由引脚供电。

上电前检查电源极性、短路、接口方向与额定电压。万用表测通断或电阻时应先断电；测电流需要正确串入电路，不能把电流档直接跨接电源。入门练习选择受限电流的低压设备，先把供电和测量方法学准确。

**接口电压必须按具体器件数据手册确认。** 例如初代 Raspberry Pi Pico 暴露的是 3.3V GPIO，不能由“USB 输入电源”推断信号脚能接 5V。[Pico 数据手册](https://datasheets.raspberrypi.org/pico/pico-datasheet.pdf)

## MCU、RTOS 和嵌入式 Linux 怎样选

MCU 适合学习 GPIO、定时器、中断、ADC 与串行接口。裸机程序可以直接使用主循环与中断；RTOS 在此基础上提供任务调度、队列和同步机制，仍需要处理有限内存和执行时序。

嵌入式 Linux 适合需要较复杂进程、网络和应用环境的设备，进一步涉及引导、设备树、驱动和根文件系统。它与裸机 MCU 的开发路径有明显差异，初学时先选一条主线。

Raspberry Pi Pico 系列属于微控制器开发板，可使用 MicroPython 或 C/C++，与运行 Linux 的树莓派单板计算机不同。[Pico 官方说明](https://www.raspberrypi.com/documentation/microcontrollers/pico-series.html)

可以用已有开发板开始：学习外设和调试时选择带有清晰原理图、示例和调试接口的板卡；有联网需求时再确认板卡自身的无线能力或外接模块。先完成一次采集与通信闭环，再考虑自制板。

## 认识几种常用外设接口

| 接口 | 常见用途 | 入门时要核对的条件 |
| --- | --- | --- |
| GPIO | LED、按键、使能信号 | 输入输出模式、电平、驱动能力、上拉下拉 |
| ADC | 模拟传感器、电压采样 | 输入范围、参考电压、采样时间、噪声 |
| UART | 日志、模块与上位机通信 | 电平标准、波特率、帧格式、交叉连接与参考地 |
| I²C | 低速传感器、配置器件 | 地址、上拉电阻、电平、总线电容与时序 |
| SPI | 显示、存储与高速外设 | 时钟极性相位、片选、速率与信号完整性 |
| PWM | LED 调光、控制信号 | 频率、占空比和负载驱动电路 |

芯片引脚通常存在复用关系。同一个脚设为模拟输入后，不能同时按另一种外设模式使用。连接前先对照板卡原理图、芯片引脚定义和外设数据手册，记录引脚分配。

## 固件从非阻塞状态机开始

传感器采集终端可以分为初始化、采样、发送和故障等待几个状态。关键是让主循环持续响应事件，避免长时间延时把按键、通信和超时处理一起阻塞。

```text
loop:
    events = collect_events()
    if sampling_deadline_reached:
        begin_or_advance_sensor_read()
    if complete_sample_available:
        validate_and_enqueue_sample()
    advance_transmission_with_timeout()
    handle_button_and_error_events(events)
```

这段是行为伪代码，具体定时器、计数器回绕处理和外设调用由目标平台实现。中断中尽量只记录事件或搬运少量数据，复杂处理交给主循环或任务；共享数据需要合适的原子操作或临界区，`volatile` 本身不能保证并发访问安全。

再引入 RTOS 时，把采集、通信与显示拆成有边界的任务，用队列传递消息。确认队列满时丢弃还是等待，明确缓冲区所有权，并检查栈空间与阻塞时间。任务数量多不代表设备更可靠。

## 调试要同时看到信号和程序状态

万用表用于核对供电与静态电平；示波器观察波形和时序；逻辑分析仪帮助解析数字总线；调试器提供断点、寄存器和内存视图。

STM32 的调试链路可参考官方 [ST-LINK 与硬件调试工具资料](https://www.st.com/en/development-tools/hardware-debugger-and-programmer-tools-for-stm32/documentation.html)。接线和工具配置以具体板卡为准，先核对目标电压、接地、调试信号与连接方式。

- **症状**：下载成功但设备没有动作。**根因候选**：启动配置、复位、引脚复用或外设时钟有误。**处理**：从复位入口设断点，检查时钟与 GPIO，再用测量验证实际引脚。
- **症状**：传感器偶尔读失败。**根因候选**：供电波动、总线时序、连接或超时处理不合理。**处理**：记录失败码和时间，同时观察电源与通信波形；避免直接用无限重试掩盖故障。
- **症状**：设备长时间运行后卡住。**根因候选**：缓冲区越界、队列阻塞、栈不足或状态机漏分支。**处理**：保留复位原因、任务和内存信息，做持续运行及断连恢复验证，再设计看门狗恢复条件。

## 用一个小终端完成验收

练习只保留一块开发板、一个传感器、一种通信方式和一个展示页面。设备定时采样，通过 UART 发送给上位机，再由上位机转给本地接口和 Web 页面；没有无线模块也能完成整条数据流。

协议至少包含设备标识、序号、时间信息、测量值、单位和错误状态。字节流通信还需要明确帧边界、长度限制与校验方式，不能假设一次读取就收到完整消息。设备运行计时与服务器时间分别记录，避免把开机时长误当成真实日期。

验收时检查：数值与参考测量相符；断开传感器能显示错误；串口短帧和乱码不会让程序失控；上位机重连能恢复；页面在等待时显示加载状态；无新数据时明确显示最后更新时间。完成这些行为，再深入 PCB、功耗优化或设备升级，会更容易理解每个技术选择的作用。
